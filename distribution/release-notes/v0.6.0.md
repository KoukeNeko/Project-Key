## New

🧠 Whole-sentence candidate ranking. On macOS, Windows, and Linux, Project Key now uses a character-level language model to rerank the ten highest-scoring sentence candidates. An infrequent word pair could previously determine the result: 「網頁太單調了」, for example, was converted to 「網液態單調了」. On the 240-sentence evaluation corpus, the number of sentences converted correctly without manual selection increased from 224 to 229. On 2,000 Wikipedia sentences excluded from training, it increased from 1,353 to 1,448.

The model runs entirely on the device and uses up to approximately 85 MB of additional memory. On an Intel Core i7-12700K, 95th-percentile processing time per key increases from approximately 1 ms to approximately 20 ms. The iOS keyboard does not include this model because of its memory limit.

## Changes

📄 The candidate window now displays the page number at the right end of the candidate row in both the collapsed and expanded states.

## Fixes

🖼️ macOS: The input source icon now fills its frame.

## 新功能

🧠 整句候選排序。macOS、Windows 與 Linux 版本現以字元級語言模型，重新排序分數最高的 10 個整句候選。先前，出現次數極少的詞對可能決定選字結果，例如將「網頁太單調了」轉換為「網液態單調了」。在 240 句評測語料中，無須手動選字即正確轉換的句子由 224 句增加至 229 句；在 2,000 句未參與訓練的維基百科句子中，由 1,353 句增加至 1,448 句。

模型完全於裝置上執行，額外使用的記憶體最高約 85 MB。於 Intel Core i7-12700K 上，每鍵處理時間的第 95 百分位數由約 1 毫秒增加至約 20 毫秒。因記憶體限制，iOS 鍵盤未納入此模型。

## 變更

📄 候選視窗於收合及展開狀態下，均在候選列最右側顯示頁碼。

## 修正

🖼️ macOS：輸入法圖示現已填滿圖示框。
