# macOS 輸入法

以 InputMethodKit 實作的注音輸入法，候選視窗採用 [A 整句校對條](../../docs/design/candidate-window/notes.md) 第 02 輪的設計。選字引擎與詞庫目前採用 McBopomofo（MIT，固定 commit）。組字與按鍵邏輯位於 `../../core/engine`，與其他平台共用，不依賴 InputMethodKit；`Sources/InputController.mm` 僅負責將按鍵與畫面接至 IMK。

## 建置與安裝

發行版（Apple 晶片）：

```bash
brew install --cask koukeneko/tap/project-key
```

亦可自 GitHub 發行版下載 `ProjectKey-<版本>-macos.pkg`，為目前使用者安裝至 `~/Library/Input Methods` 與 `~/Applications`，無須管理員密碼。此安裝檔未經簽章，自瀏覽器下載後須於「系統設定 > 隱私權與安全性」按「強制打開」。`platforms/macos/package.sh` 於 `build.sh` 之後產生此安裝檔。

自行建置須具備 Xcode（或 Command Line Tools）與 CMake，系統須為 macOS 13 以上。

```bash
platforms/macos/build.sh     # 下載並編譯引擎、產生詞庫、跑測試、輸出 build/ProjectKey.app 與 build/Project Key 設定.app
platforms/macos/install.sh   # 安裝到 ~/Library/Input Methods 並向系統註冊，設定 App 裝到 ~/Applications
```

安裝完成後開啟歡迎視窗，按「加入」即加入輸入方式；亦可於「系統設定 > 鍵盤 > 輸入方式」按「+」，於繁體中文下加入 Project Key。已加入時不再顯示歡迎視窗，日後重新安裝亦無須再次加入。

移除方式：刪除 `~/Library/Input Methods/ProjectKey.app` 與 `~/Applications/Project Key 設定.app`，再自輸入方式清單移除。

整句預覽分兩處設定：輸入時常駐於文字旁的預覽，以及選字時候選視窗下方的預覽，各有三種模式（永遠、有可疑字時、關閉），預設皆為有可疑字時，於輸入法選單的「設定…」視窗中切換，設定會儲存（輸入法選單未顯示時，以 Spotlight 或 Finder 開啟 `~/Library/Input Methods/ProjectKey.app` 亦會開啟此視窗）；⌃⇧P 開關目前所在的一處。「設定…」亦提供下列選項：

- 候選視窗與中英提示的外觀：自動（預設，依系統的淺色或深色模式）、淺色、深色，或 Liquid Glass（macOS 26 以上）。
- 選字位置：游標後或游標前。
- 鍵盤排列：大千（預設）、倚天、許氏、倚天 26 鍵、IBM。
- 開關：選完跳到下一個可疑處、簡拼、近似音（預設關閉）、聯想詞（預設關閉）、數字鍵盤選字（預設關閉）、記住選過的字、⇪ 切換中英（預設關閉）、單按 ⇧ 切換中英、⇧ Space 切換全形（預設開啟），以及 ⇥ 的英文轉注音與注音轉英文（預設開啟）。
- 記住選過的字：可清除紀錄。開啟時亦自送出的文字學習常用說法，次數存於 `~/Library/Application Support/ProjectKey/personal.txt`；每學習十萬個字串即將所有次數減半，久未使用的說法逐漸淡出；清除紀錄時一併清空。
- 恢復原廠設定：「恢復設定」將所有設定改回預設值，保留自訂詞、排除詞與選字紀錄；「一併刪除資料」另刪除這些資料（`phrases.txt`、`exclude-phrases.txt`、`personal.txt`）並清除記憶體中的選字紀錄。兩者皆保留下載的選字模型。
- 「關於」：版本、有無新版（查詢 GitHub 最新發行版；按「更新到」即下載發行版的 zip、核對 SHA-256、取代 `~/Library/Input Methods/ProjectKey.app` 並重新開啟輸入法，與 Homebrew cask 的安裝方式相同）、選字模型的日期（有新模型時可直接下載，核對 SHA-256 後無須重新安裝即生效），以及授權與引擎、詞庫的來源。

設定於下一次組字時生效。

設定 App（`~/Applications/Project Key 設定.app`，可自 Launchpad 或 Spotlight 開啟）提供同一個設定視窗，獨立於輸入法執行，輸入法未加入或未執行時亦可變更設定。其 bundle ID 為 `org.projectkey.Settings`，與輸入法不同，因此系統不會視其為第二份輸入法；設定直接寫入輸入法的 defaults（`org.projectkey.inputmethod.ProjectKey`）。輸入法記憶體中的狀態以 distributed notification 通知變更：清除選字紀錄時，設定 App 先刪除 `personal.txt` 再發出通知，輸入法確認檔案已刪除後才清空記憶體中的紀錄（其他 App 亦可發出此通知，但沙盒中的 App 無法刪除該檔案）；下載新模型後，通知輸入法改用新模型。輸入法未執行時，於下次啟動讀入這些變更。「更新到」取代的是 `~/Library/Input Methods/ProjectKey.app` 並重新開啟輸入法，設定 App 本身不隨之更新。

選單列圖示為 `icon.tiff`：強調色底上的白色「ㄅ」，與 Windows 相同。歡迎與設定視窗的 App 圖示為 `AppIcon.icns`，由 `tools/icon/make-app-icon.swift` 依 macOS 圖示格線以同一個「ㄅ」繪製。

## 可疑處的判斷

引擎所選的每個詞，若與同讀音的次一候選分數差距小於 0.5（log10），即標為可疑。使用者選過的詞不再標示。此方法僅能偵測同音詞的不確定，無法偵測斷詞錯誤，例如「重構成」被斷為「重／構成」。

## 上下文排序

存在 `tools/bigram-trainer/.cache/bigram.bin` 時，`build.sh` 將其放入 App，組字器依前兩個詞選字（bigram 與 trigram）；不存在時，選字結果與 McBopomofo 相同。同一目錄存在 `chars.bin` 時一併放入，再依前兩個字評分，補足詞模型未收錄的詞對（例如「候選」之後的 ㄘˋ 改選「字」）。同一目錄存在 `data.txt` 時，以其取代 McBopomofo 的詞庫，補充新酷音詞庫與訓練文字中 McBopomofo 未收錄的詞（例如「簽核」「氣象署」）。評測結果見 `tools/corpus-evaluator/results/`。發行版附有這三個檔案；自行建置時，可先執行 `tools/bigram-trainer/fetch-models.sh` 下載同一組檔案，或自行訓練。

組字時參考游標前的漢字，不視為句首：已送出「小模型」後輸入 ㄕˋ ㄕˋ 為「試試」，而非句首常見的「逝世」。終端機無法讀取游標前的文字，仍視為句首。

選過的字依「前一個詞＋讀音」記錄，此後相同前文優先選取該字（沿用 McBopomofo 的 UserOverrideModel，僅存於記憶體，半衰期 1.5 小時，輸入法程式重新啟動後清空）。

## 自訂詞

輸入法選單的「編輯自訂詞…」以預設文字編輯器開啟 `~/Library/Application Support/ProjectKey/phrases.txt`。每行一個詞及其注音，音節以 `-` 分隔，例如 `小鍵 ㄒㄧㄠˇ-ㄐㄧㄢˋ`；以 `#` 開頭的行為註解。存檔後於下一次組字讀入。自訂詞優先於詞庫中同讀音的詞，未加聲調時亦可查得。

同一資料夾的 `exclude-phrases.txt` 列出不再出現的詞，格式相同（`我 ㄨㄛˇ`）；詞庫與自訂詞中同讀音的該詞皆不再列為候選。輸入法選單的「編輯排除詞…」與設定的「排除詞」開啟此檔案。選字時按兩次 ⇧⌫ 或 ⌦ 排除反白的候選，即將「詞 注音」附加至此檔案並立即生效；亦可自行編輯，存檔後於下一次組字讀入，刪除檔案即恢復。

## 滑鼠

候選視窗支援滑鼠操作：點選候選字即選取，點選第一列尾端的頁碼或箭頭即展開或收合候選格線。輸入時顯示的候選列亦可點選，點選後可繼續輸入。

## 朗讀程式

選字時，候選視窗出現或反白的候選改變，即由 VoiceOver 朗讀反白的候選字及其於該列的位置，例如「程式，1/6」。VoiceOver 依焦點朗讀，而候選視窗不取得焦點，因此以朗讀通知（`NSAccessibilityAnnouncementRequestedNotification`）讀出。輸入時顯示的候選列不朗讀。
