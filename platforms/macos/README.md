# macOS 輸入法

InputMethodKit 注音輸入法（大千鍵盤），候選視窗採用 [A 整句校對條](../../docs/design/candidate-window/notes.md) 第 02 輪的設計。選字引擎與詞庫目前使用 McBopomofo（MIT，固定 commit），組字與按鍵邏輯在 `../../core/engine`，與 Windows 共用，不依賴 InputMethodKit；`Sources/InputController.mm` 只負責把按鍵與畫面接到 IMK。

## 建置與安裝

發行版（Apple 晶片）：

```bash
brew install --cask koukeneko/tap/project-key
```

也可以從 GitHub 發行版下載 `ProjectKey-<版本>-macos.pkg`，為目前使用者安裝到 `~/Library/Input Methods` 與 `~/Applications`，不需要管理員密碼。安裝檔沒有簽章，從瀏覽器下載後要到「系統設定 > 隱私權與安全性」按「強制打開」。`platforms/macos/package.sh` 在 `build.sh` 之後產生這個安裝檔。

自行建置需要 Xcode（或 Command Line Tools）與 CMake，macOS 13 以上。

```bash
platforms/macos/build.sh     # 下載並編譯引擎、產生詞庫、跑測試、輸出 build/ProjectKey.app 與 build/Project Key 設定.app
platforms/macos/install.sh   # 安裝到 ~/Library/Input Methods 並向系統註冊，設定 App 裝到 ~/Applications
```

安裝後會開啟歡迎視窗，按「加入」就會加進輸入方式；也可以到「系統設定 > 鍵盤 > 輸入方式」按「+」，在繁體中文下加入 Project Key。已經加入時不會再出現歡迎視窗，之後重新安裝也不需要再加一次。

移除：刪掉 `~/Library/Input Methods/ProjectKey.app` 與 `~/Applications/Project Key 設定.app`，再從輸入方式清單移除。

## 按鍵

| 狀態 | 按鍵 | 動作 |
|---|---|---|
| 組字中 | 注音鍵、聲調鍵 3 4 6 7 | 輸入注音；聲調鍵結束音節。按到已有注音的位置就換掉它（ㄅ 再按 ㄆ 為 ㄆ，ㄋㄧ 再按 ㄨ 為 ㄋㄨ）。聲調可省略：拼成完整音節後，位置更前面或接不上的注音開始下一個音節，不分聲調比對（ㄖㄣㄨㄟ 為「認為」）。開啟「省略聲調」（預設關）時，按到音節結尾的位置也開始下一個音節（ㄕㄉㄜ 為「是的」）。還沒結束的音節顯示注音，結束後才變成字。打字時候選視窗只有一列，列出剛打完的詞（開啟簡拼時是還沒結束的音節）的其他候選，樣子與選字時相同，猜的詞有底色；這時主鍵盤的 1–6 仍是注音，開啟「數字鍵盤選字」時數字鍵盤的 1–6 選取這一列的字。整句預覽照設定出現。方向鍵移動游標後收起。開啟簡拼（預設關）時，單獨一個注音也代表以它開頭的音節（ㄨㄇ 為「我們」），所以按到已有注音的位置就開始下一個音節；還沒結束的音節也先猜成字，列在候選列（組字區顯示「你ㄏㄠ」） |

設定 App（`~/Applications/Project Key 設定.app`，可從 Launchpad 或 Spotlight 開啟）是同一個設定視窗，獨立於輸入法執行，輸入法沒加入或沒在執行時也能改設定。它的 bundle ID 是 `org.projectkey.Settings`，與輸入法不同，所以系統不會把它當成第二份輸入法；設定直接寫入輸入法的 defaults（`org.projectkey.inputmethod.ProjectKey`）。輸入法放在記憶體裡的狀態以 distributed notification 通知：清除選字紀錄時設定 App 先刪掉 `personal.txt` 再通知，輸入法確認檔案已刪除才清空記憶體中的紀錄（其他 App 也能發這個通知，但沙盒中的 App 刪不了這個檔案）；下載新模型後通知輸入法改用新模型。輸入法沒在執行時，下次啟動就會讀到這些變更。「更新到」換掉的是 `~/Library/Input Methods/ProjectKey.app`，並重新開啟輸入法，設定 App 本身不會跟著更新。

選單列圖示是 `icon.tiff`：強調色底上的白色「ㄅ」，與 Windows 相同。歡迎與設定視窗的 App 圖示是 `AppIcon.icns`，由 `tools/icon/make-app-icon.swift` 依 macOS 的圖示格線從同一個「ㄅ」畫成。

## 可疑處的判斷

引擎走出的每個詞，若與同讀音的下一個候選分數差距小於 0.5（log10），就標為可疑。使用者選過的詞不再標示。這只能抓到同音詞的猶豫，抓不到斷詞錯誤，例如「重構成」被斷成「重／構成」。

## 上下文排序

有 `tools/bigram-trainer/.cache/bigram.bin` 時，`build.sh` 會把它放進 App，組字器依前兩個詞選字（bigram 與 trigram）；沒有時與 McBopomofo 的選字結果相同。同一個目錄有 `chars.bin` 時一併放入，再依前兩個字評分，補上詞模型沒見過的詞對（例如「候選」後的 ㄘˋ 改讀成「字」）。同一個目錄有 `data.txt` 時，以它取代 McBopomofo 的詞庫：補上新酷音詞庫與訓練文字中 McBopomofo 沒有的詞（例如「簽核」「氣象署」）。評測結果見 `tools/corpus-evaluator/results/`。發行版附上這三個檔案；自行建置時可先執行 `tools/bigram-trainer/fetch-models.sh` 下載同一組，或自行訓練。

組字接著游標前的漢字算，不當成句首：已送出「小模型」後打 ㄕˋ ㄕˋ 是「試試」，而不是句首常見的「逝世」。終端機讀不到游標前的文字，仍當成句首。

選過的字會依「前一個詞＋讀音」記下來，之後同樣的前文會優先選它（沿用 McBopomofo 的 UserOverrideModel，只存在記憶體，半衰期 1.5 小時，輸入法程式重新啟動後清空）。

## 自訂詞

輸入法選單的「編輯自訂詞…」用預設的文字編輯器開啟 `~/Library/Application Support/ProjectKey/phrases.txt`。每行一個詞和它的注音，音節以 `-` 分隔，例如 `小鍵 ㄒㄧㄠˇ-ㄐㄧㄢˋ`；`#` 開頭的行是註解。存檔後，下一次組字就會讀入。自訂詞優先於詞庫裡同讀音的詞，不打聲調時也查得到。

同一個資料夾的 `exclude-phrases.txt` 列出不要出現的詞，格式相同（`我 ㄨㄛˇ`），詞庫與自訂詞裡同讀音的這個詞都不再成為候選；輸入法選單的「編輯排除詞…」與設定的「排除詞」開啟它；選字時按 ⌦ 兩次排除反白的候選，會把「詞 注音」附加到這個檔案並立即生效；也可以自行編輯，存檔後下一次組字讀入，刪除檔案就恢復。

## 滑鼠

候選視窗可用滑鼠點選：點候選字即選取，點第一列尾端的頁碼或箭頭展開或收合候選格線。打字時顯示的候選列也可點選，點選後可繼續打字。

## 尚未實作

- 聯想詞：McBopomofo 的聯想詞資料需要另外產生。
- 淺色候選視窗（深色以外只有 Liquid Glass）。
- 整句預覽列不顯示游標位置，未完成的注音一律畫在句尾。
- 候選清單的排序仍是詞庫分數，未依前後文調整。
- Universal binary：只編譯本機架構。程式碼簽章為 ad-hoc，尚未公證，無法散布給其他電腦。

`ProjectKey --preview <資料夾>` 會把候選視窗的幾個狀態畫成 PNG，供設計檢查。
